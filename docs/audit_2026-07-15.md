# Codebase Audit — 2026-07-15

Focused audit of the hourly pipeline path and CLI. The shell/sandbox was unavailable this
session (disk space), so nothing was executed — findings are from static reading, and all
fixes below are minimal and self-contained. Recommend a `pytest tests/ -v` + `python main.py --once`
run to confirm once the environment is back.

## Root cause: `url` vs `job_url` key mismatch

Scrapers normalize every job to a **`url`** key (`scrapers/jobspy_scraper.py:28` maps the raw
JobSpy `job_url` column into `"url"`), and the DB stores/returns **`url`** (`database/db.py`).
But several modules read **`job_url`**, which is absent on pipeline jobs, so `.get("job_url")`
silently returns empty. This one mismatch caused four separate defects.

### Fixed this session

1. **Resume optimizer cache collision (high severity)** — `ai/resume_optimizer.py:387`
   read `job.get("job_url", "")`, always `""`. The cache key is `md5(job_url + resume_hash)`,
   so **every job produced the same cache key** → the first tailored resume was returned for
   all subsequent jobs. Fixed to `job.get("job_url") or job.get("url", "")`.

2. **Tailored resume never written back** — `main.py:273` matched `j.get("job_url") == r.job_url`,
   which was `None == ""` → never true, so `tailored_resume` / `resume_optimization_summary`
   were never attached to the job before saving. Fixed to compare `(j.get("job_url") or j.get("url"))`.

3. **`--optimize-resume <url>` always failed** — `main.py:505` looked up the target job by
   `job_url`, always `None` → printed "Job URL not found" for every valid URL. Fixed to fall
   back to `url`.

4. **Notion sync wrote empty URLs** — `integrations/notion_sync.py:93,206` read `job_url`.
   Fixed both to fall back to `url`.

### Not changed (out of hot path — flagging for you)

- `ai/alumni_mapper.py:206` and `ai/study_group.py:76` also read `job_url`. These aren't in
  the hourly pipeline and I didn't want to touch them without seeing their callers. If they're
  fed pipeline job dicts, apply the same `or job.get("url")` fallback.

The cleanest long-term fix is to standardize on one key. `app/models.py:203` already normalizes
(`"job_url": d.get("job_url") or d.get("url", "")`) — routing dicts through `Job.from_legacy_dict`
before enrichment would remove this whole class of bug.

## Control-flow bug in `main.py` CLI (fixed)

The `--system-design` handler never printed the LLM plan and **had no `return`**, so it fell
through into `--optimize-resume`. The missing lines had been misplaced as unreachable dead code
after the `return` in the `--optimize-top` handler (referencing an out-of-scope `plan`). Moved
the `llm_plan` print + `return` into the `--system-design` block and deleted the dead code.

## Other observations (not changed)

- **`datetime.utcnow()` is used everywhere** (`main.py`, `database/db.py`, others). The `.pyc`
  files show CPython 3.14, where `utcnow()` is deprecated and warns. Consider
  `datetime.now(timezone.utc)` in a follow-up sweep.
- **`main.py:load_config` uses `yaml.safe_load` directly**, which `CLAUDE.md` says new code
  should avoid in favor of `app.config.get_settings`. The entry point predates the `app/` layer;
  migrating it would make the Pydantic config the true single source of truth.
